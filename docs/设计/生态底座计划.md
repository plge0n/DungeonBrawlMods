# DBModKit 通用底座：生态补全计划

截至 main `f79c0ab`（DBModKit 0.18.0），ModKit 已经具备：
- 抗游戏更新：混淆名只在 `GameRaw.cs` / `Hooks.cs` / `Compat.cs` 里出现，游戏更新后用 `tools/Remap` 改名。
- Mod 运行环境：`ModContext` 生命周期和热重载、`JsonConfig`、`ModText` 多语言、`RunLog`、`ModSettings`、`GameEvents` / `Combat`，工坊 dll 加载器，`pack.ps1`。
- 修改游戏内容：`GameData`（数值表）、`AutoCast`、`MoveControl`、`ChoicePanel`、遗物发放、`SkillTuning`。
- 新增游戏内容：`PassiveSkills`、`ActiveSkills`（含 `PlayAnimation`）、`ModAssets`（图标、特效、AssetBundle）、`HeroVariants`。

现在所有新增内容都要写 C#，大部分内容作者做不了。本计划补的是"别人能基于它做 Mod"缺的部分。每一项单独开 PR，顺序见文末。

## 做之前必读

- 仓库约定：新功能从最新 main 开分支 + `git worktree`（和仓库同级的 `../wt-<名字>`），走 PR，**不动 main 的工作目录**。
- 逆向笔记 `../tools/NOTES.md`，反编译源码 `../decompiled/`。代码里有诱饵方法：内容是乱码常量和假 base64 字符串、没有调用者。判断真假要看调用者。
- **排行榜规则（游戏作者定的，不能绕过）**：装了 Mod 不能上传排行榜。ModKit 拦了两处：`bwu.quj`（自己上传）和 `bbe.ktb`（在别人房间里把国王快照交给房主）。任何新内容都不能让改过的数据流到别人那里上传。
- **改玩法的内容只在单人时生效**：`Game.IsSolo`，和 DBStudio 玩法包、变体英雄一样。第 2 项做完后，改成由联机握手统一决定。
- 部署：main 有部署前检查（#16），编译测试项目要加 `-p:DeployToGame=false`，或者用 `-p:DeployDir=<临时目录>` 部署到别处。引用 DBModKit 的测试项目，在 ProjectReference 上加 `AdditionalProperties="DeployToGame=false"`，否则被引用的 DBModKit 会被部署进游戏，覆盖别人正在测的版本。
- 每个改了 ModKit 的 PR 都要跑：
  `dotnet run --project tools/Remap -c Release -- selftest --old ../backup/6.45 --mutate 0.03`，要求"DBModKit 用到的"全对、改写后 0 编译错误。
  新增的游戏成员要加进 `Compat.cs`（**同一个键不要写两次**，字典初始化器会让后一条覆盖前一条）。
- 版本号：几个分支同时开发时容易撞号（feat/mod-menu 已经占了 0.19.0）。开 PR 时取"当前 main 的版本 + 1 个小版本"，合并前如果撞号，按合并顺序顺延。
- 0.15~0.18 加的被动、主动、资源、施法动作、变体、国王快照拦截都**还没实机测试**，正在另一个对话里测。如果测试发现接口要改，以那边的结论为准。

## 1. 内容包：不写代码也能做 Mod（最优先）

**目标**：内容作者只用 JSON + 图片/AssetBundle 就能做出技能、被动、变体英雄、数值改动，通过工坊分发，ModKit 直接加载，不需要 dll。

**格式**：工坊条目（或本地 `BepInEx/content/<名字>/`）根目录放 `dbmod.json`，`"Type": "content"`（现在只认 `plugin` / `runtime`，见 `Workshop.cs`）。示例：
```json
{
  "Format": 1, "Type": "content", "Name": "雷霆套装", "Author": "…", "Version": "1.0.0", "MinModKit": "0.20.0",
  "Content": ["skills.json", "variants.json"],
  "Lang": "lang"
}
```
`skills.json` 示例（字段和 `ActiveSkillDef` / `PassiveSkillDef` / `HeroVariantDef` 一一对应，键名用 camelCase）：
```json
{
  "activeSkills": [{
    "key": "nova", "name": "雷暴", "description": "对范围内敌人造成 {0} 点伤害",
    "icon": "assets/nova.png", "indicator": "Range", "cost": 20, "cooldown": 8, "range": 3, "duration": 2,
    "damageBase": 100, "damageValue": 1.5,
    "onCast":   [ { "effect": "Effect/SpellThunder", "duration": 1.5 }, { "damage": "area" } ],
    "onTick":   { "every": 0.5, "do": [ { "damage": "area", "scale": 0.25 } ] },
    "animation": { "game": "Frank_RPG_2Hand_Skill01_WhirlWind", "duration": 2 }
  }],
  "passiveSkills": [{
    "key": "blade", "name": "饮血之刃", "values": [20, 5],
    "onAdded": [ { "addStats": { "str": "{0}" } } ],
    "onHit":   [ { "heal": "damage * {1} / 100" } ]
  }]
}
```

**内置效果库**（行为用 JSON 组合，在 ModKit 里实现成 `ActiveSkill` / `PassiveSkill` 的通用子类）：
- 伤害：`damage`，可以是 area / target / line（矩形用 `ez.dxs`）；`scale` 乘公式伤害；可选 `radius`。
- 治疗：`heal`；加蓝：`mana`；加金币：`gold`（只在单人时生效）。
- 加属性：`addStats` / `addAttackSpeed` / `addArmor`，失去时自动撤销。限时增益：`buff`（秒数）。
- 表现：`effect`（游戏路径，或内容包里注册的特效）、`animation`、`notice`。
- 触发器：onCast、onTick、onEnd、onAdded、onRemoved、onHit、onKill、onCrit、onHurt、onWaveStart。
- 条件：`chance`、`hpBelow`、`isBoss`、`cooldown`（内部冷却）。
- 表达式：只支持 `{n}`（Values）、`damage`、`maxHp`、`str/agi/sta/attack` 和四则运算，自己写一个小解析器，不要引入脚本引擎。

DBStudio 的规则引擎（`DBStudio/RuleEngine.cs`、`Rules.cs`）已经有一套"当…如果…就…"的条件和动作。先看它能不能下沉到 ModKit 复用，避免两套。

**加载**：ModKit 启动时扫描工坊和本地内容包。和 dll 条目不同，内容包不执行代码，所以不需要逐个确认，但要能在 Mod 列表里关掉（feat/mod-menu 在做 Mod 列表，和它对接）。JSON 出错时写进 RunLog，并在 Mod 列表里显示原因，不能让整个 ModKit 停用。

**工具**：`pack.ps1` 支持把内容包目录打成工坊条目。`templates/ContentPack/` 放一个最小示例。DBStudio 可以加一个"从玩法包导出内容包"（后续再做）。

**验收**：示例内容包放进 `BepInEx/content/`，游戏里能从技能书抽到它定义的技能和被动，效果和用 C# 写的一致；JSON 写错一个字段时，Mod 列表显示具体错误，其他内容照常加载。

## 2. 联机握手：统一决定自定义内容能不能用

**问题**：现在是各自为政。变体、玩法包看 `Game.IsSolo`；自定义技能在联机时照样能用（没装 Mod 的人看不到效果，但不会出错）；数值类 Mod 在联机时会影响队友。

**做法**：
- 用现成的大厅成员数据通道（`LobbySync`，Steam 大厅；局域网模式没有大厅），每个人公布"ModKit 版本 + 启用的 Mod/内容包列表和版本"。
- ModKit 提供 `Multiplayer.Policy`：Solo（只有自己）/ AllHaveSame（所有人装了同样的内容）/ HostAllowed（房主勾选"本局允许"，并提示所有人）/ Blocked。
- 自定义内容声明自己的级别：Cosmetic（外观，随时可用）/ Gameplay（改玩法，需要 AllHaveSame 或 HostAllowed）。`PassiveSkillDef`、`ActiveSkillDef`、`HeroVariantDef`、内容包都加这个字段；被动、主动的技能书候选池按策略动态加入或移除。
- 进入地牢前（大厅阶段）检查一次，进地牢后锁定，本局不再变。把现在散落的 `Game.IsSolo` 判断换成这个。
- DBStudio 的"本局允许玩法包"（见项目记忆 / DBStudio 代码）迁到这里统一实现。

**注意**：
- 不能注册自定义 Mirror 消息，收到未知消息 id 时会断线（NOTES"联机同步通道"）。只用大厅成员数据。
- 握手结果只决定"本地是否启用"，不能借此往没装 Mod 的人那边发任何东西。

**验收**：两个人联机——都装同样内容时 Gameplay 内容可用；一人没装时自动停用并提示；房主勾选后可用，所有人都收到提示。

## 3. 更多可注册的内容

按价值排序，每类一个 PR，写法参照 `PassiveSkills`（注入原始表 `cx.zyc[...]` + 类型化的表 `cj.boyl.*` + 创建实例的工厂补丁 + `ez.ebf` / `bax.ker` 过滤）：
1. **遗物**（`RemainsData`，`cj.boyl.bcry`，发放 `bbe.kqk`，效果名到 `rn` 子类的映射在 `bbe.kql`，见 NOTES"遗物"）：自定义遗物进遗物三选一，行为用 `RelicBehaviour`（获得、失去、每帧、升级）。构筑上传（`ez.ebj` 的 relic 数组）要过滤掉。
2. **卡牌**（`cj.boyl.bcsc`）、**装备**（`bcsl`、`equipment` 表）：先调研发放和效果的代码路径，再决定做不做。
3. **怪物 / Boss**：联机时怪物由房主生成，涉及同步，放到联机握手之后，只在 AllHaveSame 时可用。

每一项都要写清楚：对没装 Mod 的人有没有影响、构筑数据怎么过滤、重试波次（`wb`）快照下会不会出问题。

## 4. 接口稳定、文档、示例

- **接口约定**：1.0 之前可以改；1.0 之后公开接口只增不改，要删就先标 `[Obsolete]` 保留一个小版本。在 README 里写明。
- **文档**：README 的接口速览表已经很长了，拆到 `docs/api/` 每个模块一页（用途、示例、联机行为、限制）。可以从 XML 注释生成，但示例要手写。
- **示例 Mod**：`samples/` 下放 3 个完整的 Mod，不进 sln、不打包：自定义被动 + 主动、变体英雄、带 AssetBundle 的技能（图标、特效、动作）。编译时 DeployToGame=false。
- **AssetBundle 工程模板**：游戏是 Unity 2022.3（准确版本用 `Application.unityVersion` 查）。给一个最小 Unity 工程或打包脚本说明，包括 Humanoid 动作片段、粒子特效预制体、图标 Sprite 的导入设置。
- `tools/new-mod.ps1` 加选项：生成带技能示例的 Mod。

## 5. Mod 之间的依赖和冲突

- `dbmod.json` 增加 `Dependencies`（工坊物品号或 GUID + 最低版本）。加载器按依赖排序，缺依赖时在 Mod 列表里提示，并给出工坊链接。`Workshop.cs` 现在只看 BepInDependency。
- 冲突检测：两个 Mod 注册同一个 Key 不会冲突，因为编号由 GUID+Key 决定；但两个 Mod 用 `GameData` / `SkillTuning` 改同一项数值、或 `AutoCast` / `MoveControl` 争夺处理器时，要在 Mod 列表里提示。`AutoCast.SetHandler` / `MoveControl.SetHandler` 现在是后注册的覆盖先注册的，需要明确规则。

## 建议顺序

1. 第 2 项的最小版本：公布 Mod 列表 + `Multiplayer.Policy` + Cosmetic/Gameplay 级别。它会影响第 1 项的设计，所以先定接口。
2. 第 1 项内容包（大头，可以拆成"加载器 + 格式"和"效果库"两个 PR）。
3. 第 4 项：示例和文档（内容包有了以后最需要）。
4. 第 3 项：遗物。
5. 第 5 项。

每个 PR 写清楚：静态调研的证据（文件:行号）、编译和 Remap 自测结果、实机测试清单（未实测要明说）。
