# 打榜资格与打榜模式（0.40.0）

游戏作者已同意：只显示信息和只替玩家操作、不改数值的白名单 Mod 可以打榜。名单由 DBModKit 固定维护，其他 Mod 不能通过 API、配置、声明或内容包自行加入。

## 只读接口

在 Unity 主线程调用，每次读取都重新检查。结果是当前状态，不能作为之后上传的许可；ModKit 在真正上传和发送国王快照时再次检查。

```csharp
bool canUpload = Ranked.Eligible;
IReadOnlyList<string> reasons = Ranked.Reasons; // 给玩家看的中文短句，只读快照
bool rankedModeThisProcess = Ranked.ModeActive; // 本次启动固定
string status = ModList.RankedStatus; // 能上传 / 不能上传 + 原因
```

`Eligible` 和 `Reasons` 分别读取会分别检查，不保证跨调用原子一致。不要每帧轮询；设置界面每秒刷新即可。检查结果和原因写入 RunLog。任何检查异常均按不合格处理。

检查插件表、隐藏或未激活的插件对象、ScriptEngine 脚本程序集、全部 Harmony 补丁 owner、`BepInEx/patchers` 中递归找到的 DLL、已加载内容包，以及主动技能、被动、遗物、装备、装备特效、英雄变体注册表。即使变体只换外观也不合格。卡牌全解锁开关和永久写入不参与资格检查。

当前白名单 Mod 没有独立的 Harmony 实例。只允许 `plge0n.dungeonbrawl.modkit` 和 `plge0n.dungeonbrawl.modkit.cards` 两个 owner。ScriptEngine、UnityExplorer 和所有脚本插件都不合格；从脚本目录加载白名单 Mod 也不能让开发环境获得资格。

当前有一个尚待规则确认的阻塞：原装 BepInEx 5.4.23.5 自带 `org.bepinex.fixes.harmonyinterop` 和随机 `harmony-auto-*` owner 的核心运行时兼容补丁。严格执行上述 owner 规则也会拦截它们，因此当前默认环境即使只装白名单也会不合格。没有擅自把启动器补丁加入豁免；需要确认是否允许精确核验的原装核心补丁后才能解决。详见项目外验收结果和逆向笔记“打榜白名单”。

## 打榜模式对作者的影响

配置 `DBModKit.cfg` 对应 GUID 文件 `plge0n.dungeonbrawl.modkit.cfg` 的 `[General] RankedMode` 默认 `false`。主菜单 Mod 窗口也可切换。启动时读一次；改动后必须重启，关闭后再重启恢复正常加载。不开打榜模式、只装白名单 Mod 也可以打榜。

打榜模式下，白名单以外的 `ModContext.Start` 会返回一个 `RankedDisabled == true` 的上下文，不调用 `OnLoad`，不登记玩法握手，不调用 `OnUnload`。插件列表显示“打榜模式下停用”。该插件只有声明依赖 ModKit、身份与被停用实例相符、且其程序集没有任何 Harmony 补丁时，才能作为“已停用”豁免。未依赖 ModKit 的第三方插件仍阻止打榜。

请把事件订阅、注册内容、修改数值、游戏对象的创建和设置界面注册都放进 `OnLoad`，在 `OnUnload` 中清理；`Awake` 仅调用 `ModContext.Start`，`OnDestroy` 仅释放上下文。ModKit 无法阻止第三方 `Awake` 自行改游戏。不要自行伪造白名单 GUID、Harmony owner 或大厅资格。

工坊代码插件在实例化前按 GUID 过滤，非白名单不实例化。内容包从创意工坊、`workshop-dev`、`BepInEx/content` 等来源统一不加载，不能在本次运行重新开启。用户的启用配置保持原选择，退出打榜模式后恢复。

打榜模式只保留排行榜保护、卡牌保护、自动释放（含开关技能）、走位、波次事件、伤害上下文和原始伤害观察；命中事件订阅继续工作。怪物倍率、男枪弹药、致命伤害拦截、撕咬/炸弹、噬魂溅射、皮肤、自定义技能/被动/遗物/装备/变体、Mod 图标/特效及重试快照不安装。相应 `Available` 为 `false`。重试快照和图标属于保守跳过；未来白名单功能需要时必须重新核实。

## 联机

现有玩法握手 `dbmods.mods` 的格式不变。新增独立大厅成员字段 `dbmods.ranked`：`1|UTC秒|0或1|首条原因UTF-8的Base64`。合格时原因为空。每秒公布本机结果，不包含队友，避免循环依赖；上传时本机现算并读取其他成员最近公布的数据。

所有读取 `Ranked` 的客户端都检查可见的 ModKit 队友。房主在排行榜入口决定是否上传整队，非房主只控制自己的国王快照；合格时原参数和原版流程不变，不合格时拦截。原版房主不受 ModKit 控制，客户端不合格时不发快照，原版房主仍能上传不含该玩家快照的成绩。

有 `dbmods.mods` 或资格字段的玩家按 ModKit 玩家处理：旧版没有新字段、格式错误、数据超过 10 秒未刷新或比本机时间快 5 秒以上，一律不合格。两个字段均不可见的玩家按原版处理。没有 Steam 大厅的联机无法确认队友，保守判不合格。SteamID 用于原因中的队友标识。大厅数据基于各端自报，不是防作弊证明；时钟偏差、网络延迟、进程暂停可能导致保守拦截。

**没有实机测试**：只检查编译和主菜单日志；真实结算、联机及模式恢复需在游戏中验证。


AutoForge（自动锻体）0.40.0：白名单 Mod，可以打榜。F10 开关（Ctrl+F10 仍为 RunLog 标记）；在 Mod → AutoForge → 设置调整属性权重或均衡模式。不自动购买锻造器；联机只操作本机。没有实机测试，只检查启动到主菜单。

打榜模式安装 ForgingHooks（档次与原生选择确认）及 CheckpointHooks（只发重试通知，不执行 SkillTuning 快照）；均归 ModKit 主 owner，无新 owner。
