# 依赖和冲突

玩家在 Mod 设置 → DBModKit → **依赖和冲突** 里能看到下面所有问题，代码里用 `ModConflicts.All()` 读。

## 依赖（dbmod.json 的 Dependencies）

工坊插件条目和内容包都可以写：

```json
"Dependencies": [
  { "Guid": "example.dungeonbrawl.skillsample", "Name": "SkillSample", "MinVersion": "1.0.0", "Workshop": 3800000000 },
  { "Guid": "author.thunder" }
]
```

- `Guid`：插件的 GUID，或内容包的 `Id`（写成 `content:author.thunder` 也行）。
- `MinVersion`：最低版本，不写就不检查。`Workshop`：工坊物品号，缺这个依赖时会出现"订阅 …"按钮，点了打开工坊页面（订阅要玩家自己点）。
- **插件条目**只能依赖插件（`[BepInDependency]` 也照常检查）。依赖在同一批工坊条目里时，会排在后面加载；缺依赖时条目显示"缺少依赖"，
  之后允许了别的条目、依赖到齐了会再试一次。
- **内容包**可以依赖插件和别的内容包，会排在依赖的包后面加载；依赖不满足时整个包不加载，互相依赖时报"依赖之间有循环"。
  关掉一个内容包，依赖它的包也会跟着停用。

## 只能有一个 Mod 接管的功能

`AutoCast`（自动释放）和 `MoveControl`（走位）同一时间只有一个处理器生效。规则：

1. 玩家在"依赖和冲突"里指定了哪个 Mod，就用它（`AutoCast.Prefer(guid)` / `MoveControl.Prefer(guid)`，会保存）。
2. 没指定，或者指定的 Mod 没装，就用**先注册的**。
3. 后注册的排队；生效的那个卸载后自动轮到下一个。同一个 Mod 热重载重新注册时保留原来的位置。

`AutoCast.Owner` / `Contenders` 读现在的情况。以前是"后注册的覆盖先注册的"，0.23.0 改成了上面的规则。

## 其他冲突

| 情况 | 怎么处理 |
|---|---|
| 两个 Mod 用 `GameData.Set` 改了同一项数值 | 后改的生效，列出来提醒 |
| 一个 Mod 用 `GameData.Load` 载入改动时清掉了别的 Mod 改过的项 | 只剩后载入的，列出来提醒（`GameData` 只该有一个 Mod 管，见[数值与三选一](数值与三选一.md)） |
| 两个内容包的 `Id` 一样 | 只用先扫描到的那个（工坊 → workshop-dev → BepInEx/content） |
| 同一个技能被几个 Mod 用 `SkillTuning` 调整 | 倍率相乘，标成"叠加"，不一定是问题 |
| 两个 Mod 注册同一个 Key 的技能、遗物 | 不冲突：编号由 GUID + Key 算出 |
